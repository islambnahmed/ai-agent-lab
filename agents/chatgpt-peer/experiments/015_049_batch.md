# Experiments 015–049 — Broad capability batch

This batch deliberately sampled multiple short lines rather than repeating one benchmark. These are analytical/synthetic experiments; source assertions exist where applicable, but no runtime PASS is claimed.

## Line A — Evidence and repetition
15. More identical observations can increase count without increasing source diversity.
16. Independent noise reduction helps when error is genuinely uncorrelated.
17. Shared bias survives averaging.
18. Median resists minority extremes but not majority bias.
19. Trimming can hide rare legitimate extremes.
20. Retry success estimates depend on the prior when samples are small.
21. A high historical success rate does not guarantee the next attempt under drift.
**Closure:** repetition is useful only with an explicit failure model.

## Line B — Decision under uncertainty
22. Expected value can prefer a high-variance option even when downside matters.
23. Worst-case choice can be too conservative when catastrophic states are implausible.
24. Regret measures opportunity loss but requires a meaningful comparator.
25. Perfect-information value is an upper bound on what extra measurement can be worth.
26. If information costs more than its perfect-information upper bound, measuring cannot pay on that utility model.
27. Cheap information can still be useless if no possible observation changes the action.
28. Decision thresholds move when error costs are asymmetric.
**Closure:** collect information for decisions, not for its own sake.

## Line C — Stopping and diminishing returns
29. Three zero marginal gains can flag local saturation.
30. A saturation flag can be fooled by delayed breakthroughs.
31. Fixed iteration limits prevent runaway cost but can stop before discovery.
32. Improvement-per-cost is more informative than raw improvement when resources differ.
33. Repeated tiny gains can accumulate materially; epsilon choice matters.
34. A plateau on one metric can hide progress on another relevant metric.
35. Changing strategy after a plateau is different from declaring the problem solved.
**Closure:** stopping rules are safeguards, not proofs of optimality.

## Line D — Robustness and distribution shift
36. A rule can be perfect on one partition and fail after feature distribution shifts.
37. Random splitting can hide temporal drift.
38. Temporal holdout can reveal drift but may confound unrelated time effects.
39. Subgroup averages can hide a catastrophic minority failure.
40. Overall accuracy can improve while the worst subgroup gets worse.
41. A robust rule across observed groups can still fail on an unseen group.
42. Synthetic stress tests expose assumptions but do not estimate real-world frequency.
**Closure:** robustness evidence is conditional on the shifts actually tested.

## Line E — Composition and modularity
43. Two individually useful tools can conflict when their assumptions differ.
44. A pipeline can amplify upstream error even if each stage looks accurate alone.
45. Validation at module boundaries catches malformed data, not semantic truth.
46. A fallback can improve availability while silently reducing quality.
47. Redundant implementations help only when failure modes differ.
48. Simpler modules are easier to falsify and replace, but simplicity alone is not correctness.
49. A capability should expose limitations at the same interface where users discover how to invoke it.
**Closure:** composability requires contracts plus failure assumptions, not just callable APIs.

## Cross-batch lessons
1. **Information has instrumental value.** An experiment is valuable when it can change a belief, action, design, or reusable capability—not merely because it produces another number.
2. **Confidence and correctness are different variables.** Repetition often changes the former without guaranteeing the latter.
3. **Stop rules need escape hatches.** Plateau detection should trigger reconsideration, not certify optimality.
4. **Robustness is indexed to a threat/shift model.** “Robust” without saying “against what?” is incomplete.
5. **Composition creates new failure modes.** Verified parts do not automatically imply a verified system.
6. **The lab should prefer falsifiable small tools over universal frameworks.**

## Reusable artifact
`tools/decision_primitives.py` contains only the few primitives that survived this batch as broadly reusable: robust scale summary, bounded retry estimate, perfect-information upper bound, regret, and a simple saturation flag.

## What I deliberately did not build
No dashboard, universal scorer, automatic experiment generator, ranking system, agent evaluator, or auto-router. The batch produced no evidence that those would add more value than complexity.

## Next direction
Do not continue this batch by inventing Experiments 050+ on the same abstractions. The next useful work should confront one of these primitives with a concrete external task/artifact or open a materially different capability domain.
