# Khepri experiment 414 — Reward-Semantics Audit

2026-10-24. Synthetic research only; no real crawling, trading, production calls, or external actions.

## Question

Experiment 413 found that a better Poisson interval-censoring estimator increased a scheduler's **binary-hit reward**. Does this imply the data is fresher? **No.** We replay the same refresh schedules against multiple operational objectives, including time spent stale.

Reference: experiment 413 censored_refresh.py, branch khepri/exp413-censored-refresh-20261024, Git blob 0ceac2df83969fef5626bfbdd2543e0f2e87932f. This experiment reproduces its MAP likelihood, prior and tie-breaking, but generates latent integer Poisson counts and exposes **only binary feedback** to the policies. The underlying counts are used exclusively to score outcomes.

## Distinct reward definitions

- **binary_hits (maximize):** impact × one when at least one change occurred since last refresh; multiple changes count once (experiment 413 objective).
- **timely_events (maximize):** sum over actual events of impact × exp(-detection_delay / 1.5), for events detected within the horizon. Assumes separate events have separate value.
- **stale_days (minimize):** impact-weighted days when the cache is stale **before** that day's check.
- **stale_days_after (minimize):** same after that day's check. This avoids dependence on a single intra-day accounting convention.

## Exact counterexample (no statistical uncertainty)

Two sources over six days, one check/day. Source A impact 6, changes every day. Source B impact 5, changes only on day 0.

- Schedule X checks A on all six days: **36 binary-hit points**, **66 pre-check stale-day points**.
- Schedule Y checks B on day 0, then A on days 1–5: **35 binary-hit points**, **41 pre-check stale-day points**.

X strictly wins binary hits but strictly loses freshness.

## Paired Monte Carlo evidence

150 replicates per domain; 90 days, five items, two checks/day; seed 414. Each policy sees the **same latent event counts** within a replicate. Policies: censored MAP, naive positive-as-one, oracle *true-rate myopic binary-hit* (not globally optimal), round-robin, and a true-rate daily freshness proxy. None sees future realized events.

| Domain | Binary hits: censored / naive (higher better) | After-check stale days: censored / naive (lower better) |
| --- | --- | --- |
| SEO | 419.61 / 373.44 (+12.36%) | 408.41 / 365.73 (+11.67% worse) |
| Feed | 778.23 / 741.41 (+4.97%) | 797.93 / 748.72 (+6.57% worse) |
| High churn | 1089.79 / 1004.13 (+8.53%) | 973.63 / 822.75 (+18.34% worse) |

For SEO, paired censored-minus-naive binary-hit gain is +46.17 (approximate 95% CI [43.37, 48.97]), while the **after-check stale-day cost increases by +42.67** (CI [29.2, 56.1]). These CIs describe variation under the synthetic generator, not real-world certainty.

All three domains show this objective ranking reversal. Additional outcomes and CI values are generated by benchmark.py. Exact tests include the counterexample, no-future-leakage, binary accounting parity, and staleness invariants.

## Reproduce

Python 3.10+, standard library only. From this directory:

    python -m unittest -v test_reward_audit.py
    python benchmark.py

The benchmark writes results.json with fixed seeds. Locally, 18/18 tests passed and the 450-replicate benchmark took ~26 seconds.

## Limits and decision consequence

This does **not** show the censored estimator is mathematically worse. It may estimate rates more accurately while the **scheduler objective is wrong for the user's actual goal**. The processes are independent, stationary Poisson, with perfect binary detection, fixed impact and check budgets. The stale-days metric presumes last-write-wins freshness matters; timely-events presumes each event matters. Neither can be asserted universally.

**Reusable lesson:** specify the business objective before optimizing the model or celebrating a benchmark gain; test at least one conflicting objective. Next experiment should design an objective-aligned or Pareto-aware scheduler under uncertain/changing rates.
